# خطوات إصلاح مشاكل الاتصال بقاعدة البيانات وسياسات RLS

## المشكلة الرئيسية:
بناءً على رسائل الخطأ، يبدو أن المشكلة الرئيسية هي في سياسات أمان الصفوف (RLS) في Supabase. المستخدم يمكنه تسجيل الدخول بنجاح (لديك User ID: d0a2bd88-996c-40bd-aed3-a2fa1b03d915)، لكنه لا يستطيع الوصول إلى البيانات في الجداول المختلفة مثل transactions و categories و budgets و products و user_settings.

## خطوات الإصلاح:

### الخطوة 1: إنشاء ملف .env
1. أنشئ ملف `.env` في المجلد الرئيسي للمشروع
2. أضف المتغيرات التالية إلى الملف:
```
VITE_SUPABASE_URL=https://polfltbnbzdwdfznlxwp.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6InBvbGZsdGJuYnpkd2Rmem5seHdwIiwicm9sZSI6ImFub24iLCJpYXQiOjE3NDc1NDU4ODksImV4cCI6MjA2MzEyMTg4OX0.KwJNDuDBMLDbBftujEtD_CGwEk6n6WuOBm09O5b1Lhw
```

### الخطوة 2: إصلاح سياسات RLS
1. قم بتسجيل الدخول إلى لوحة تحكم Supabase الخاصة بمشروعك
2. انتقل إلى قسم SQL Editor
3. انسخ محتويات ملف `fix_rls_permissions.sql` الذي تم إنشاؤه وقم بلصقه في محرر SQL
4. قم بتنفيذ الاستعلام

هذا الملف سيقوم بما يلي:
- تمكين RLS على جميع الجداول الرئيسية
- حذف سياسات RLS القديمة التي قد تكون مسببة للمشكلة
- إنشاء سياسات جديدة تسمح للمستخدمين بالوصول إلى بياناتهم الخاصة
- التحقق من وجود الجداول المطلوبة وإنشائها إذا لم تكن موجودة

### الخطوة 3: إعادة تشغيل التطبيق
1. بعد تنفيذ الاستعلام SQL، قم بإعادة تشغيل خادم التطوير (Vite):
```
npm run dev
```
أو
```
yarn dev
```

### الخطوة 4: التحقق من الإصلاح
1. قم بتسجيل الدخول إلى التطبيق
2. تحقق من أن البيانات تظهر الآن في الصفحات المختلفة
3. تحقق من عدم ظهور رسائل خطأ "Permission denied for table" في وحدة تحكم المتصفح

## ملاحظات إضافية:
1. **مشكلة HTML في DashboardPage**: هناك تحذير في وحدة التحكم يشير إلى وجود عنصر `<ol>` داخل عنصر `<p>` في صفحة لوحة التحكم، وهو غير صالح من ناحية HTML. يمكن إصلاح ذلك بتعديل ملف `DashboardPage.tsx` لضمان أن عنصر `<ol>` ليس داخل عنصر `<p>`.

2. **إعداد الجداول**: إذا استمرت مشاكل الوصول إلى الجداول، قد تحتاج إلى تنفيذ ملف `create_required_tables.sql` الموجود في جذر المشروع لإنشاء هيكل قاعدة البيانات بالكامل.

3. **البيانات الأولية**: قد ترغب في إنشاء بعض البيانات الأولية مثل الفئات والحسابات لتسهيل استخدام التطبيق.

4. **تتبع الأخطاء**: إذا استمرت المشاكل، راقب وحدة تحكم المتصفح بحثًا عن رسائل خطأ جديدة وقم بمعالجتها واحدة تلو الأخرى.
