# خطوات إصلاح مشاكل الاتصال بقاعدة البيانات وسياسات RLS

## المشكلة الرئيسية:
بناءً على رسائل الخطأ، هناك مشكلتان رئيسيتان:
1. عدم وجود ملف `.env` لتخزين بيانات الاتصال بـ Supabase
2. مشاكل في سياسات أمان الصفوف (RLS) في Supabase
3. بعض الجداول غير موجودة مثل جدول "reports" (خطأ: ERROR: 42P01: relation "reports" does not exist)

## خطوات الإصلاح:

### الخطوة 1: إنشاء ملف .env
1. أنشئ ملف `.env` في المجلد الرئيسي للمشروع
2. أضف المتغيرات التالية إلى الملف:
```
VITE_SUPABASE_URL=https://polfltbnbzdwdfznlxwp.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJzdXBhYmFzZSIsInJlZiI6InBvbGZsdGJuYnpkd2Rmem5seHdwIiwicm9sZSI6ImFub24iLCJpYXQiOjE3NDc1NDU4ODksImV4cCI6MjA2MzEyMTg4OX0.KwJNDuDBMLDbBftujEtD_CGwEk6n6WuOBm09O5b1Lhw
```

### الخطوة 2: إصلاح هيكل قاعدة البيانات وسياسات RLS
1. قم بتسجيل الدخول إلى لوحة تحكم Supabase الخاصة بمشروعك
2. انتقل إلى قسم SQL Editor
3. انسخ محتويات ملف `fix_rls_permissions_updated.sql` الذي تم إنشاؤه وقم بلصقه في محرر SQL
4. قم بتنفيذ الاستعلام

هذا الملف المحدث سيقوم بما يلي:
- التحقق من وجود جميع الجداول المطلوبة وإنشائها إذا لم تكن موجودة (بما في ذلك جدول reports)
- تمكين RLS على جميع الجداول الرئيسية
- حذف سياسات RLS القديمة التي قد تكون مسببة للمشكلة
- إنشاء سياسات جديدة تسمح للمستخدمين بالوصول إلى بياناتهم الخاصة (فقط للجداول الموجودة)

### الخطوة 3: إعادة تشغيل التطبيق
1. بعد تنفيذ الاستعلام SQL، قم بإعادة تشغيل خادم التطوير (Vite):
```
npm run dev
```
أو
```
yarn dev
```

### الخطوة 4: التحقق من الإصلاح
1. قم بتسجيل الدخول إلى التطبيق
2. تحقق من أن البيانات تظهر الآن في الصفحات المختلفة
3. تحقق من عدم ظهور رسائل خطأ "Permission denied for table" أو "relation does not exist" في وحدة تحكم المتصفح

## ملاحظات إضافية:

### 1. التعامل مع الخطأ "relation does not exist"
الملف المحدث `fix_rls_permissions_updated.sql` يقوم بإنشاء جميع الجداول المطلوبة قبل محاولة تطبيق سياسات RLS عليها. كما أنه يتحقق من وجود الجدول قبل إنشاء السياسات عليه لتجنب أي أخطاء.

### 2. مشكلة HTML في DashboardPage
هناك تحذير في وحدة التحكم يشير إلى وجود عنصر `<ol>` داخل عنصر `<p>` في صفحة لوحة التحكم، وهو غير صالح من ناحية HTML. يمكن إصلاح ذلك بتعديل ملف `DashboardPage.tsx` لضمان أن عنصر `<ol>` ليس داخل عنصر `<p>`.

### 3. إنشاء بيانات أولية
بعد إنشاء الجداول، قد ترغب في إضافة بعض البيانات الأولية مثل الفئات والحسابات لتسهيل استخدام التطبيق. يمكنك استخدام واجهة Supabase Studio لإضافة هذه البيانات يدويًا.

### 4. تتبع الأخطاء
إذا استمرت المشاكل، راقب وحدة تحكم المتصفح بحثًا عن رسائل خطأ جديدة وقم بمعالجتها واحدة تلو الأخرى. تأكد من أن جميع الجداول المشار إليها في الكود موجودة في قاعدة البيانات.

### 5. استخدام ملفات SQL الأخرى
إذا كنت بحاجة إلى إعداد قاعدة البيانات بالكامل، يمكنك استخدام ملف `complete_database_schema.sql` الموجود في جذر المشروع، ولكن تأكد من تنفيذ ملف `fix_rls_permissions_updated.sql` بعد ذلك لإعداد سياسات RLS بشكل صحيح.
